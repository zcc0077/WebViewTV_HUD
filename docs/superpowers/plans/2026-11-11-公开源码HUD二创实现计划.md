# 公开源码 HUD 二创实现计划

**目标：** 从官方公开源码直接构建支持默认全屏、display 2 HUD 播放和可调设置的独立应用，并推送现有仓库。

**架构：** 官方 Kotlin 播放链路负责网页与全屏；HUD Java 组件负责授权、窗口迁移与编辑器，通过稳定接口读取播放器尺寸。纯 Java 策略隔离几何、默认值和生命周期决定，方便本地测试。

**技术栈：** Android Gradle Plugin、Kotlin、Java、Android API 28 基线、JUnit、模拟器。

## 任务

- [x] 构建：恢复 :app，固定可取得的依赖版本、全部 ABI、debug 签名与 API 28/30 兼容；验证 :app:assembleDebug。构建负责人仅修改 Gradle/工具脚本。
- [x] 红灯：默认 auto_fullscreen/pip_enabled=true、保存 false 可读回；前后台策略仅 Home 且播放中才进入 HUD，成功后保持播放，否则暂停；缺屏不安装窗口。几何使用现有三组回归。
- [x] 实现：SettingsManager 接入默认值，AppSettingsView 加两项开关及 HUD 设置；MainActivity 接入 Home/Resume/Stop/Destroy；播放器实现稳定尺寸/比例接口，移除旧反射依赖。
- [x] 播放恢复：为清空的列表提供可读 JSON 入口、内置最小合法网页列表与自定义 URL；测试空列表和越界源，避免首页崩溃。
- [x] 测试：Gradle 单元测试与 Lint；API 28 模拟器实际编辑器交互、保存/取消/重开、默认全屏和本地视频播放；副屏模拟与前后台恢复。
- [x] 交付：移除默认树中的反编译工作副本，README 更新来源、构建、功能、验证限制及签名说明。检查敏感信息、暂存/分支 Markdown 与实际范围，合并提交、推送并回读远端 SHA。

## 验证边界

本轮保留同一播放器跨屏迁移；已撤回未经证据支持的网页 CSS HUD 和重建播放器方案，不引入网页重载。窗口/编辑器验证与视频像素验证分别记录：API 28 模拟器系统 WebView 66 的视频像素检查没有通过，主屏截图也为黑帧，不作为已通过的验收。诊断可用 instrumentation 参数 verifyVideoPixels=true 显式启用。实车已安装的旧 APK 没有更新；源码版实际视频输出仍需实车验证。

最终本地结果：27 项 JUnit、4 项 Node 脚本测试、5 项 API 28 窗口/设置交互测试通过；Debug 构建与 Lint 通过（Lint 0 errors，仍有上游警告）。视频像素诊断不包含在上述通过数量内，其失败记录已在 README 单独说明。
